Product Requirements Document (PRD)
Title:
Web2 Holes in Web3 Armor: SSRF & Broken Auth in Off-Chain Signers

1. Objective
To demonstrate how common Web2 vulnerabilities—Server-Side Request Forgery (SSRF) and Broken Authentication—can be used to compromise Web3 systems through off-chain infrastructure like metadata fetchers and signing relayers. The project includes:

Two hands-on labs (mini web apps with security flaws)

A long-form research article

Clear documentation and exploitation demos

2. Target Audience
Web3 developers and backend engineers

Smart contract security researchers

Bug bounty hunters

Web3 startups and protocol teams

Hackathon judges evaluating security awareness

3. Problem Statement
Many Web3 protocols neglect traditional Web2 security practices in off-chain services, leading to catastrophic failures even when smart contracts are safe. The goal is to raise awareness and offer educational, reproducible resources that show how Web2 vulnerabilities can lead to Web3 compromise.

4. Scope
Included:
Two self-contained labs with:

One SSRF vulnerability

One Broken Authentication vulnerability

A detailed blog post (~1,500 words)

Screenshots, code samples, and exploit demos

GitHub repositories with README, PoC scripts, and mitigation tips

Not Included:
Real blockchain deployments or live wallets

Frontend UIs beyond what’s necessary for demo

5. Features
A. Lab 1: SSRF in Metadata Fetcher

Feature	Description
Vulnerable metadata fetcher	Accepts external URL input (e.g. NFT metadata) and makes requests
Exploitable SSRF	Attacker uses internal IPs or localhost to extract data or trigger services
Simulated Web3 tie-in	SSRF may fetch internal keys, initiate transaction signing, or read internal APIs
Secure version	Includes mitigation with whitelisting or proxy pattern
B. Lab 2: Broken Authentication in Signer API

Feature	Description
Transaction signing endpoint	Relayer API simulates signing and sending transactions
Broken Auth	Lacks token auth, or has hardcoded/shared API key
Exploit	Attacker sends transaction to be signed and executed
Secure version	Shows token-based and RBAC enforcement as fix
6. User Workflow
👨‍💻 Lab Users (Security Researcher / Hacker):
Visit GitHub repo and follow README instructions.

Run Docker container or use npm install && node index.js to launch the vulnerable app.

Read attack scenario in README.

Use:

cURL or Postman for HTTP exploits (e.g., SSRF payloads)

Python script for API attack (e.g., relayer abuse)

Observe logs or results (e.g., sensitive data leak or fake fund transfer).

Compare to remediated version (included in repo).

Use screenshots and logs for educational or reporting purposes.

🧑‍🏫 Article Readers:
Access blog post via Medium/Substack/Notion.

Read intro on Web2 risks in Web3.

Explore case studies (e.g., time.fun, Harmony Bridge).

Read about SSRF & Broken Auth, their exploitation & remediations.

Follow links to labs on GitHub.

Learn how to secure their off-chain infra using checklists and tooling suggestions.
